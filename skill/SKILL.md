# 阶梯式上下文瘦身

**它不是压缩。** 压缩把一整轮折成摘要，原话就没了；瘦身只拿掉过程，话留在原地。

## 什么时候升哪一层

**从低往高升，一次只升一级，升完看效果再决定要不要继续。**

| 层 | 舍什么 | 什么时候用 |
|---|---|---|
| `level: 1` | 工具参数 | 先试这个。写文件、跑命令的 arguments 往往最占地方 |
| `level: 2` | L1 + 整个工具 | L1 之后还紧。调用块和结果节点成对消失，那轮看起来像没用过工具 |
| `level: 3` | L2 + 思考链 | 还紧。这一步之后旧轮次就只剩你俩说过的话了 |

## 三条硬规矩

1. **别跳级。** 能 L1 解决的事别用 L3——每舍一样，下一轮能想起来的东西就少一样。
2. **L4 之前必须走完 L1–L3。** L4 是"正文也折成摘要"，那一步交给 `compress`，不是这个工具。只有前三层都做完还不够时才碰它。
3. **先 `dryRun`。** 看 `argsCleared` / `resultsSquashed` / `reasoningStripped` 三个数，觉得动得对再真跑。

## 它怎么做的（决定了很多边界）

写一条 `plugin:dsh-context-slim/rewrite` 记录进日志，再在消息投影里把那几个 seq 覆盖成瘦身版。**不动 surface，不改原事件**——原始内容一个字没删，`session_event_read` 按事件号能读回全的。

要撤回就再写一条把那些 seq 映射回原消息：后写的盖先写的。**但别指望这个**，先 dryRun。

## 幂等

已经瘦过、且级别够的 seq 会被跳过。跑完立刻再跑一遍同样的命令，计数应该全是 0。

**一个不是 bug 的例外**：`keepTurns` 是滑动的。每过几轮，之前护着的"最近 N 轮"会滑出保护圈，成为新的可瘦身对象——那时计数又不是 0，这是对的。
